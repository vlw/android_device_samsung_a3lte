# A3 model-specific device-tree images

The kernel is compiled once with `lineageos_a3_defconfig`. `variants.mk` passes
an explicit DTB list to kernel Make without changing model Kconfig options:

| Image | DTS revisions | QCDT v2 entries |
| --- | --- | --- |
| dtF.img | a3-eur r00, r01 | 8 |
| dtFU.img | a3u-eur r01 | 4 |
| dtH.img | a33g-eur r00, r01, r03, r04 | 20 |

These are seven DTBs and 32 selection entries across three separate QCDT
containers. A DTB can produce multiple entries for supported chipset/board IDs.
F/FU and early F/H trees share selection keys, so a single mixed container is
ambiguous. `dt.img` is byte-identical to `dtF.img` for the default boot image.

`bootimg.mk` retains Samsung's boot format and replaces only DT packaging.
It tracks DTS/includes and performs an incremental `dtbs` check even when a
DTS-only change leaves zImage unchanged. Kati tracks all four output files;
deleting any image regenerates the set. Unchanged files retain timestamps so
restat avoids rebuilding consumers when the generated bytes did not change.
Boot also depends explicitly on the kernel: this branch omits it from
INTERNAL_BOOTIMAGE_FILES, so DT restat alone must not keep an old kernel in boot.

Each model is staged in its own temporary directory. `build_dtimages.py` checks
selection-key uniqueness within that model and validates every QCDT entry and
its DTB payload after dtbTool runs. This catches dtbTool silently skipping a
duplicate. All variants must validate before any output is published.

The images and existing recovery-side repack tools enter target-files under
`RADIO/` (an archive transport directory, not modem flashing). Releasetools
reads them from its input archive, checks the model tables and verifies that
`BOOT/dt` equals `RADIO/dtF.img`. Missing or inconsistent artifacts stop OTA
generation; old target-files without the new artifacts must be rebuilt.
There is no fallback to vendor's old dtFU.img/dtH.img.

Installation still leaves F's default boot unchanged, selects FU/H using the
existing bootloader-string checks, and repacks only their DT section. The
Samsung bootloader chooses a hardware revision inside the selected QCDT table
before passing the DTB to Linux. Recovery is not replaced.

Build all images with the normal product environment:

    lunch lineage_a3lte-eng
    m dtimage

Outputs are `out/target/product/a3lte/{dt.img,dtF.img,dtFU.img,dtH.img}`. Normal
boot/OTA builds use the same rules. Host tests:

    python3 device/samsung/a3lte/dtimages/test_dtimages.py
    python3 device/samsung/a3lte/dtimages/test_boot_dependency.py

This integration does not change DTS hardware values. In particular, the
previous F/FU-specific memory/ramoops overrides are not automatically copied
to H; H memory tuning needs its own stock comparison and validation.
